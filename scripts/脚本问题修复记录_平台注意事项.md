# 脚本问题修复记录 & 平台脚本编写注意事项

> 版本：v1.1（2026-08-15）
> 适用：`bedrock_host_check.sh`（Linux/macOS/bash）、`bedrock_host_check.ps1`（Windows/PowerShell）
> 本文档记录两个脚本在真机运行中遇到的问题、根因、修复方法，以及编写跨平台脚本时应规避的常见坑。
> 变更：v1.0 → v1.1 新增第 7 条（ps_lines 二次 grep 误报修复）

---

## 一、运行中遇到的问题、原因与修复

### 1. bash 版握手静默失败（误报"不可达"）

**现象**：在 Windows 上跑 bash 版脚本，RakNet 握手总是 FAIL，输出 `无响应: `（空），即使目标服务器明明存活。

**根因**：脚本用 `command -v python3 || command -v python` 查找 Python。Windows 的 `C:\Users\<user>\AppData\Local\Microsoft\WindowsApps\python3` 是一个 **Microsoft Store 占位 stub**（`AppInstallerPythonRedirector.exe`）。调用它时无任何输出就立即退出（实际会引导去商店装 Python），导致 `OUT=` 为空 → 脚本误判握手失败。

**修复**：新增 `find_real_python()` 函数——逐个尝试 `python` / `python3` / `py`，**跳过路径含 `WindowsApps` 的占位符**，并实际执行 `python -c 'import sys'` 验证它是能跑的真实解释器。

**验证**：修复后 bash 版对 `192.168.0.35:19132` 正确输出 `PASS ✅` 及完整 MOTD。

---

### 2. bash 版 `ignored null byte in input` 警告

**现象**：每次运行都打印 `bedrock_host_check.sh: line 60: warning: command substitution: ignored null byte in input`。

**根因**：第 60 行 `MAGIC=$(printf '\x00\xff...')` 生成的字符串含 **NUL 字节（0x00）**。bash 变量不能存储 NUL 字节，命令替换时将其丢弃并告警。而且这个 `MAGIC` 变量其实**从未被使用**（Python 内联代码里是硬编码的 magic 字节）。

**修复**：删除这行无用的 `MAGIC` 变量定义。

**验证**：运行不再出现该警告。

---

### 3. bash 版本机模式泄漏 Python Traceback

**现象**：本机模式（无基岩服务）握手时，输出里混入 `Traceback (most recent call last) ... ConnectionResetError: [WinError 10054]` 原始堆栈，不够干净。

**根因**：内联 Python 只捕获了 `socket.timeout`，而 Windows 上向未监听的 UDP 端口发包会触发 `ConnectionResetError`（ICMP 端口不可达），未被捕获。

**修复**：Python 代码增加 `except OSError as e: print(f"SOCKET_ERROR|{e}")` 捕获通用 socket 错误。

**验证**：本机模式干净输出 `FAIL ❌ (无响应: SOCKET_ERROR|[WinError 10054] ...)`，无 Traceback。

---

### 4. PowerShell 版 ParserError（中文乱码导致解析失败）

**现象**：`powershell -File bedrock_host_check.ps1 -Help` 报 `ParserError`，错误信息里的中文字符显示为乱码 `�?`。

**根因**（两个叠加）：
1. **编码问题**：脚本保存为 **UTF-8 无 BOM**。Windows PowerShell 5.1 默认按系统 ANSI 代码页（中文系统为 GBK）读取无 BOM 的 `.ps1`，导致中文被错误解码成乱码，进而破坏字符串的引号/括号 → ParserError。
2. **语法问题**：`Write-Host "...($HostAddr:$Port ...)"` 中，PowerShell 会把 `$HostAddr:` 解析为"带冒号的变量/驱动器限定名"（`$Var:` 是合法语法，表示 Scope 或 drive），紧跟 `:` 后无合法变量字符时报 `Variable reference is not valid`。

**修复**：
1. 给 `.ps1` 文件头添加 **UTF-8 BOM**（字节 `EF BB BF`），让 PS 5.1 正确识别为 UTF-8。
2. 将 `$HostAddr:$Port` 改为 `${HostAddr}:${Port}`（用 `${}` 显式界定变量名）。

**验证**：`pwsh 7` / `powershell 5.1` 均能正常解析并输出帮助。

> **注意**：在 git-bash 终端直接查看 PS 脚本输出仍可能显示乱码，但那是**终端显示层**用 GBK 渲染 UTF-8 文本造成的，文件本身编码是正确的。判断是否真乱码，应重定向到文件再用正确编码读取。

### 5. PowerShell 版 MOTD 为空

**现象**：握手判定 PASS（Geyser 存活），但 `MOTD:` 后面是空的。

**根因**：MOTD 解析逻辑读错偏移。原代码从 `data[32:34]` 读 uint16 长度、再用 UTF-16LE 解码 `data[34...]`。实测 Geyser 的 Pong 响应：**MOTD 文本从偏移 34 一直延伸到包尾，编码是 UTF-8，且长度字段并不可靠**（读 offset 33 得到 0，读 offset 32 得到 30720 等错误值）。

**修复**：改为直接取 `data[34..]` 剩余全部字节，用 `[System.Text.Encoding]::UTF8` 解码并去掉尾部 `\0`。bash 版同步改为 `data[34:].decode("utf-8")`。

**验证**：PS 版正确输出完整 MOTD（`qMCPE;PaperMC Server | welcome;...`）。

---

### 6. bash 版进程检查依赖 `pgrep`（部分环境缺失）

**现象**：MSYS git-bash、busybox、部分精简 Linux 镜像没有 `pgrep`，进程检查静默返回空，显示"未找到 Geyser 进程"，即使服务在跑。

**根因**：`pgrep` 不是 POSIX 标准命令，精简/非 GNU 环境可能缺失。

**修复**：新增跨平台 `find_proc()`——有 `pgrep` 则用 `pgrep -f -i`，否则回退 `ps aux || ps -ef`，再由 `ps_lines()` 统一 `grep -i -E` 匹配并过滤 grep 自身。

**验证**：在无 `pgrep` 的机器上回退路径实测能正确匹配到 `bash` 进程、匹配不存在项返回空。

---

### 7. ⚠️ `ps_lines()` 二次 grep 误报"未找到进程"（v1.1 自查发现并修复）

**现象**：服务端明明在跑，进程检查却显示「无 Geyser/服务端进程 ❌」。

**根因**：`find_proc()` 有 pgrep 时返回的是 **pid 数字**（如 `32400`），`ps_lines()` 再对 pid 做 `grep -E "paper.*jar"` 文本匹配——**pid 数字里永远匹配不到进程名**，结果恒为空 → 误报。macOS/BSD 的 `pgrep -af` 同样只输出 pid（不支持 `-a` 扩展），不能用来二次 grep。

**修复**：统一走 `ps aux || ps -ef` + `grep -i -E`（ps 输出含完整命令行，可匹配）；pgrep 仅作为快速存在性判断，不再参与输出匹配。

**验证**：macOS 实测正确输出「服务端运行中 (Geyser 可能内嵌) ⚠️」+ 完整 java 命令行。

## 二、跨平台脚本编写注意事项

### 通用（bash / 跨平台）

| # | 注意事项 | 说明 |
|---|---------|------|
| 1 | **脚本声明 `#!/bin/bash`，别用 `sh` 调用含 `[[ ]]` 的脚本** | `[[ ]]` 是 bash 特有语法，`sh`(dash) 会报语法错误。用户请用 `bash xxx.sh` |
| 2 | **`command -v` 找命令要验证"真能用"** | Windows 有大量 Store 占位 stub（`python3`、`node` 等）。找到后最好实际执行一次 `xxx -c '...'` 验证，并跳过 `WindowsApps` 路径 |
| 3 | **`pgrep` 非 POSIX**，优先回退 `ps aux`/`ps -ef` | 进程匹配用 `find_proc` + `grep` 双回退，兼容 busybox/精简 Linux |
| 4 | **`ss`/`netstat` 二选一** | 二者输出格式不同（macOS `udp46`、Linux `udp`），用 `command -v` 检测后各自解析 |
| 5 | **命令替换里别放 NUL 字节** | `$(printf '\x00...')` 会告警且丢失 NUL，bash 变量存不了 NUL；如需二进制用内联语言硬编码 |
| 6 | **命令参数智能识别要区分"纯数字=端口"** | 用 `[[ $1 =~ ^[0-9]+$ ]]` 判断，避免把端口当 host |
| 7 | **外部命令失败会污染输出** | Python 等子进程要捕获 `OSError`/`socket.timeout`，输出统一走约定前缀（如 `PASS/FAIL`），便于外层 grep 判断 |

### PowerShell（Windows）

| # | 注意事项 | 说明 |
|---|---------|------|
| 1 | **含中文的 `.ps1` 必须存成 UTF-8 带 BOM** | PS 5.1 按 ANSI 读无 BOM 文件会乱码→ParserError。用带 BOM 的 UTF-8（字节 `EF BB BF`）两者通吃 |
| 2 | **`$Var:` 会被解析成驱动器/Scope** | 字符串里要输出 `$host:$port` 必须写 `${host}:${port}`，否则报 `Variable reference is not valid` |
| 3 | **`Get-NetFirewallRule` 需要管理员** | 用 try/catch 降级：无权限时提示"跳过"，不中断脚本 |
| 4 | **管理员/普通权限差异** | 计划：防火墙检查需管理员；普通权限自动跳过该项 |
| 5 | **UDP socket 收包要先设 `ReceiveTimeout`** | 否则阻塞，用 `$client.Client.ReceiveTimeout = ms` 设超时 |
| 6 | **字节解析注意字节序** | `[BitConverter]::GetBytes(int64)` 是小端，发送网络字节序要 `[Array]::Reverse` |

### 网络 / 基岩协议

| # | 注意事项 | 说明 |
|---|---------|------|
| 1 | **基岩版走 UDP（RakNet），TCP 通 ≠ UDP 通** | 排查时不要被"能 ping 通/能连 TCP"误导 |
| 2 | **RakNet Pong 的 MOTD 从偏移 34 到包尾** | 长度字段不可靠，直接取剩余字节 + UTF-8 解码最稳 |
| 3 | **本机装 Clash/VPN（TUN 模式）会劫持 UDP 与 DNS** | 公网 UDP 出站可能全被拦截、nslookup 返回假 IP（如 `198.18.x.x`）。局域网直连通常不受影响。验证公网 UDP 需在免代理环境或外网机器进行 |
