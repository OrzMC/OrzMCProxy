# 基岩版 Geyser 连通性诊断脚本 — 使用说明

> 版本：v1.1（2026-08-15）
> 适用：排查 Minecraft 基岩版入口（Geyser）连通性问题
> 包含：`bedrock_host_check.sh`（Linux/macOS）、`bedrock_host_check.ps1`（Windows）
> 变更：v1.0 → v1.1 修复多个跨平台 bug 并增强可移植性，详见《脚本问题修复记录_平台注意事项.md》

## 1. 脚本能做什么

一条命令完成基岩版入口诊断，自动区分问题出在哪里：

| 检查项 | 说明 | 本机模式 | 远程模式 |
|:--|:--|:--:|:--:|
| [1] RakNet 握手 | 真实基岩协议握手，判断 Geyser 是否存活，返回服务器 MOTD | ✅ | ✅ |
| [2] 端口监听 | UDP 端口是否真的在监听 | ✅ | ⏭️ |
| [3] 进程检查 | Geyser 独立进程 / 内嵌服务端 | ✅ | ⏭️ |
| [4] 防火墙 | Windows 防火墙 / macOS / ufw / firewalld 规则 | ✅ | ⏭️ |
| [5] 外部提示 | 提醒 UDP 需单独放行（TCP 通 ≠ UDP 通） | ✅ | ⏭️ |

**两种模式**：
- **本机模式**（默认）—— 在服务器宿主机上运行，查 Geyser 死活 + 本机防火墙（五项全查）
- **远程模式** —— 传 host 即可，测试任意服务器的基岩入口可达性（等价 bedrock_ping.py）

## 2. bash 版（Linux / macOS / Windows git-bash）

### 环境要求
- `python3` **或** `python`（RakNet 握手用；脚本会自动检测真实解释器，**跳过 Windows 的 Store 占位 stub**）
- `netstat` 或 `ss`（端口监听检查用）
- 无需 root 可跑完核心 4 项；防火墙细节建议管理员跑
- **跨平台**：兼容 macOS/Linux（含精简版）、Windows git-bash；进程检查统一走 `ps aux/-ef + grep`（兼容无 pgrep 环境；pgrep 仅作快速存在性判断，不参与匹配输出）

### 用法

```bash
bash bedrock_host_check.sh                    # 本机 19132（最简）
bash bedrock_host_check.sh 39742              # 本机 39742（纯数字=端口）
bash bedrock_host_check.sh mc.example.com     # 远程 19132（只写 host）
bash bedrock_host_check.sh mc.example.com 39742
bash bedrock_host_check.sh -h                 # 查看帮助
```

### 参数智能识别

| 第一个参数 | 判定 | 目标 |
|:--|:--|:--|
| 不传 | 本机模式 | 127.0.0.1:19132 |
| 纯数字（如 `39742`） | 视为**端口** | 本机 :39742 |
| 域名 / IP | 视为 **host** | 远程 :19132（默认端口） |
| `-h` / `--help` | 显示帮助 | — |

## 3. PowerShell 版（Windows）

### 环境要求
- Windows PowerShell 5.1+（Win10/Win11 自带）
- **无需安装 Python**（纯 PowerShell 实现握手）
- 防火墙检查项需**管理员权限**；普通权限会自动跳过该项，不中断
- ⚠️ **文件编码**：`bedrock_host_check.ps1` 必须保存为 **UTF-8 带 BOM**，否则 Windows PowerShell 5.1 会按 ANSI 读取导致中文乱码、解析报错（用 PowerShell 7 / pwsh 则更稳妥）

### 用法

```powershell
powershell -ExecutionPolicy Bypass -File .\bedrock_host_check.ps1
powershell -ExecutionPolicy Bypass -File .\bedrock_host_check.ps1 -Port 39742
powershell -ExecutionPolicy Bypass -File .\bedrock_host_check.ps1 mc.example.com
powershell -ExecutionPolicy Bypass -File .\bedrock_host_check.ps1 mc.example.com -Port 39742
powershell -ExecutionPolicy Bypass -File .\bedrock_host_check.ps1 -Help
```

## 5. 典型排障流程

```
场景: 基岩版客户端连不上 mc.example.com:19132

步骤1: 本机跑  bash bedrock_host_check.sh mc.example.com
        → 不可达 → 继续
步骤2: 在服务器宿主机上跑 bash bedrock_host_check.sh（本机模式）
        ├─ 本机 PASS + 监听 ✅ → 问题在路由器/云防火墙 UDP 转发
        └─ 本机 FAIL / 未监听 → Geyser 没跑 / 端口错 / 本机防火墙拦
```

**关键认知**：
- 基岩版走 **UDP**（RakNet 协议），TCP 通 ≠ UDP 通
- 云服务器安全组、家用路由器**必须单独放行 UDP 端口**（如 19132/39742）
- 修改 Geyser 端口：`plugins/Geyser-Spigot/config.yml` 的 `bedrock.port`

## 6. 常见问题 FAQ

| 问题 | 答案 |
|:--|:--|
| 报 `python3: command not found` | 装 Python 3 或用 PowerShell 版 |
| Windows 上 bash 版握手总 FAIL 但服务器明明在 | 旧版会命中 Microsoft Store 的 `python3` 占位 stub；v1.1 已自动跳过（`find_real_python`），确保用真实 `python` |
| PowerShell 版报 ParserError / 中文乱码 | 脚本必须是 **UTF-8 带 BOM**；另外 `$Var:` 请用 `${Var}:` 写法（v1.1 已修） |
| macOS 防火墙那项显示"需 root" | 正常，非管理员看不到应用列表；用 `sudo bash bedrock_host_check.sh` 可看全 |
| 远程模式显示超时但 TCP 能连 | 典型 UDP 未转发，检查安全组/路由器 UDP 规则 |
| 本机装了 Clash/VPN 后公网 UDP 全超时 | TUN 模式会劫持 UDP 与 DNS；局域网直连通常不受影响，公网验证请在免代理环境 |
| MOTD 显示乱码 | 正常现象，某些服务器返回编码特殊，不影响判断 |
| 想测 Java 版端口 | 本脚本只测基岩（RakNet UDP）；Java 版用 `nc -zv host 25565` 或 mc_ping_probe.py |
